# Resume Screening System

An NLP-based system that ranks candidate resumes against a job description using TF-IDF vectorization and cosine similarity, so a recruiter can shortlist a batch of applicants by relevance instead of reading every resume manually.

Built as an academic project (B.E. Computer Engineering, Mumbai University Rev. 2019 syllabus) by Adyan Shaikh.

## How it works

1. **Text extraction:** pulls raw text out of resume PDF/DOCX files.
2. **Preprocessing:** lowercases the text, removes URLs, email addresses, digits and punctuation, tokenizes (NLTK), removes English stop words, keeps alphabetic tokens only, and lemmatizes (WordNet).
3. **Feature extraction:** converts the cleaned text into TF-IDF vectors (unigrams and bigrams, up to 5,000 features, sublinear term frequency), fit on the resumes together with the job description so they share one vocabulary.
4. **Similarity scoring:** computes cosine similarity between each resume vector and the job description vector.
5. **Ranking:** sorts resumes by score, highest first, and reports the score as a percentage.

## Two ways to use it

| Script | Question it answers | Who it's for |
|---|---|---|
| `run_screening.py` | "I have one open role. Who is the best fit among these candidates?" | Recruiter / HR (the system's primary purpose) |
| `match_categories.py` | "I have this resume. Which of many job types does it fit best?" | Candidate self-check, or a validation tool |

## Measured results

Benchmarked on the Kaggle Resume Dataset (2,484 resumes, 24 job categories) using 500 labeled resume–job description pairs:

- **Relevant pairs (250):** a resume paired with the job description of its own category.
- **Not-relevant pairs (250):** a resume paired with one randomly chosen job description from a different category.
- **Split:** 100 validation pairs and 400 held-out test pairs (stratified, seed 42). Each method's decision threshold was tuned on the validation pairs (maximizing F1, grid 0.01 to 0.95 in steps of 0.01) and then applied unchanged to the test pairs.

| Method | Accuracy | Precision | Recall | F1-score | Threshold |
|---|---|---|---|---|---|
| Keyword Matching | 68.00% | 68.95% | 65.50% | 67.18% | 0.33 |
| Bag-of-Words + Cosine | 74.00% | 72.64% | 77.00% | 74.76% | 0.11 |
| **TF-IDF + Cosine** | **82.00%** | **86.78%** | 75.50% | **80.75%** | 0.06 |

- TF-IDF + Cosine is the most precise method (fewest false positives); Bag-of-Words has slightly higher recall.
- The TF-IDF method differs from the Bag-of-Words baseline in more than IDF weighting. It also uses bigrams, sublinear term frequency and a 5,000-feature cap, so the gap reflects the whole TF-IDF configuration.
- An auxiliary Multinomial Naive Bayes classifier that predicts a resume's category directly reaches 53.9% accuracy across the 24 classes (chance is about 4%).
- **Speed:** roughly 4–5 ms per resume for text preprocessing and 1–2 ms per resume for TF-IDF + cosine scoring (amortized over a batch), measured on the author's laptop. These figures exclude PDF text extraction and vary by hardware and run.

## Setup

```bash
pip install -r requirements.txt
python -c "import nltk; [nltk.download(r) for r in ('stopwords','wordnet','omw-1.4','punkt','punkt_tab')]"
```

`data/Resume.csv` comes from the Kaggle [Resume Dataset](https://www.kaggle.com/datasets/snehaanbhawal/resume-dataset) by S. Bhawal. If it isn't in your copy of the repo, download it from Kaggle and place it at `data/Resume.csv`.

## Usage

The two screening scripts need resumes to score. Put your own PDF/DOCX files in `data/raw_resumes/` first.

**Recruiter mode:** rank resumes against a specific job.
```bash
# Use one of the 24 built-in job categories
python src/run_screening.py --resumes_dir data/raw_resumes --jd_category "INFORMATION-TECHNOLOGY"

# Or supply your own job description
python src/run_screening.py --resumes_dir data/raw_resumes --jd_file my_job_posting.txt
```
Output: `output/ranked_resumes.csv` (filename and match percentage, sorted descending).

**Candidate/validation mode:** find the best-fitting category for each resume.
```bash
python src/match_categories.py --resumes_dir data/raw_resumes
```
Output: `output/best_category_matches.csv` (best match and top 3 per resume) and `output/category_match_matrix.csv` (full resume × category similarity matrix).

**Reproduce the benchmark:** this uses only `data/Resume.csv`, not the resume folder.
```bash
python src/evaluate.py                # full run: recomputes everything
python src/evaluate.py --replot-only  # regenerates the figures from saved results (needs a prior full run)
```

## Known limitations

- Lexical overlap only: it cannot recognize synonyms or paraphrased skills (for example "developer" vs. "programmer").
- No deep contextual understanding, unlike transformer-based models such as BERT.
- Accuracy depends on resume text quality; unusual PDF layouts or scanned images can degrade text extraction.
- It cannot assess soft skills, cultural fit, or anything outside the resume text.
- Benchmark relevance labels are proxied by job-category match, not human judgment, and the job descriptions were written by the author. The benchmark uses the dataset's pre-extracted text, not raw PDFs.
- Results come from a single seeded split of 500 pairs.

## Future scope

- Semantic embeddings (for example Sentence-BERT) to catch paraphrased or synonymous skills.
- Named Entity Recognition to separate skills, degrees and experience.
- A web interface (for example Streamlit) for non-technical recruiters.
- Integration with Applicant Tracking Systems.

## Data and privacy

No resumes are included in this repository; `data/raw_resumes/` is empty. Resumes contain personal information, so don't commit real ones. The Kaggle dataset has its own terms of use on its Kaggle page.
